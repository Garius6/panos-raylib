# raylib для panos

Библиотека-обёртка над [raylib](https://www.raylib.com/) для языка
[panos](https://github.com/Garius6/panos), написанная поверх настоящего
динамического FFI (`внешний`/`ff_структура`, Стадии 47-51) — panos core
ничего не знает про raylib, это обычная `.pns`-библиотека, как любая
другая.

## Требования

- Установленный raylib: `brew install raylib` (macOS).
- **Единственная проверенная платформа — macOS/Apple Silicon.** Путь к
  библиотеке захардкожен в `raylib.pns`
  (`/opt/homebrew/opt/raylib/lib/libraylib.dylib`) — честно
  задокументированный пробел, не скрытый. На Intel-Mac/Linux путь нужно
  поправить вручную (см. "Известные ограничения" ниже).
- panos с поддержкой `внешний`/`ff_структура` (Стадия 51+).

## Установка

panos пока не имеет пакетного менеджера ([`pan`](https://github.com/Garius6/panosiki)
в разработке) — библиотека распространяется как обычный файл. Скопируйте
`raylib.pns` в директорию своего проекта (рядом с исходником, который его
импортирует, или в поддиректорию `модули/`):

```
$ cp raylib.pns путь/к/вашему/проекту/
```

## Использование

```panos
импорт raylib

функ старт() -> Пусто
    raylib.инициализировать_окно(800, 450, "моё окно")
    raylib.задать_fps(60)

    пока raylib.окно_должно_закрыться() == ложь цикл
        raylib.начать_рисование()
        raylib.очистить_фон(raylib.Цвет(20, 20, 20, 255))
        raylib.нарисовать_прямоугольник(raylib.Вектор2(100.0, 100.0), raylib.Вектор2(50.0, 30.0), raylib.Цвет(255, 0, 0, 255))
        raylib.нарисовать_круг(raylib.Вектор2(300.0, 200.0), 25.0, raylib.Цвет(0, 255, 0, 255))
        raylib.закончить_рисование()
    конец

    raylib.закрыть_окно()
конец
```

Полный рабочий пример — [`pong.pns`](./pong.pns). Он использует весло
игрока (стрелки вверх/вниз), простой ИИ-соперник, счёт печатается в
консоль при пропущенном мяче.

```
$ panos pong.pns
```

## API

### Окно и цикл отрисовки

- `инициализировать_окно(ширина: Целое, высота: Целое, заголовок: Строка) -> Пусто`
- `окно_должно_закрыться() -> Булево` — `истина`, когда пользователь
  закрыл окно (крестик/Esc).
- `закрыть_окно() -> Пусто`
- `начать_рисование()` / `закончить_рисование()` — окружают каждый кадр,
  всё рисование (`нарисовать_*`) действует только между ними.
- `задать_fps(fps: Целое) -> Пусто`
- `время_кадра() -> Число` — секунды с прошлого кадра (`dt`), для
  движения, не зависящего от FPS.

### Рисование

- `очистить_фон(цвет: Цвет) -> Пусто`
- `нарисовать_прямоугольник(позиция: Вектор2, размер: Вектор2, цвет: Цвет) -> Пусто`
- `нарисовать_круг(центр: Вектор2, радиус: Число, цвет: Цвет) -> Пусто`
- `нарисовать_прямоугольник_пиксели(x, y, ширина, высота, цвет) -> Пусто`
- `нарисовать_текст(текст, x, y, размер, цвет) -> Пусто`

### 3D

3D API построен поверх настоящих функций raylib, а не поверх
псевдо-3D-отрисовки:

- `камера_перспективы(позиция, цель, вверх, угол_обзора) -> Камера3D`
- `начать_3d(камера)` / `закончить_3d()`
- `нарисовать_куб(позиция, ширина, высота, глубина, цвет)`
- `нарисовать_текстурный_куб(текстура, позиция, ширина, высота, глубина, оттенок)`
- `нарисовать_контур_куба(позиция, ширина, высота, глубина, цвет)`
- `нарисовать_сферу(центр, радиус, цвет)`
- `нарисовать_плоскость(центр, размер: Вектор2, цвет)`
- `нарисовать_сетку(секции, шаг)`

### Текстуры и модели

- `загрузить_текстуру(путь) -> Текстура2D` / `освободить_текстуру(текстура)`
- `сохранить_матрицу_модели()` / `восстановить_матрицу_модели()`
- `сдвинуть_модель(x, y, z)` и `повернуть_модель(угол, ось_x, ось_y, ось_z)`

### Рендер в текстуру

Для пиксельной графики можно рисовать в небольшой `РендерТекстура2D`, а затем
растянуть её на окно без сглаживания:

- `создать_рендер_текстуру(ширина, высота) -> РендерТекстура2D`
- `начать_рисование_в_текстуру(цель)` / `закончить_рисование_в_текстуру()`
- `текстура_из_рендер_текстуры(цель) -> Текстура2D`
- `задать_пиксельную_фильтрацию(текстура)` — nearest-neighbour
- `нарисовать_текстуру_растянутую(текстура, источник, назначение, оттенок)`
- `освободить_рендер_текстуру(цель)`

`kirgu_defense.pns` использует буфер 320×180, растянутый до 960×540: это
даёт крупный пиксель и характерную картинку консолей пятого поколения.

Минимальная сцена:

```panos
пер камера = raylib.камера_перспективы(
    raylib.Вектор3(4.0, 3.0, 6.0),
    raylib.Вектор3(0.0, 1.0, 0.0),
    raylib.Вектор3(0.0, 1.0, 0.0),
    60.0
)
raylib.начать_3d(камера)
raylib.нарисовать_плоскость(raylib.Вектор3(0.0, 0.0, 0.0), raylib.Вектор2(20.0, 20.0), raylib.Цвет(45, 75, 55, 255))
raylib.нарисовать_куб(raylib.Вектор3(0.0, 1.0, 0.0), 2.0, 2.0, 2.0, raylib.Цвет(240, 150, 50, 255))
raylib.закончить_3d()
```

### Типы

- `Вектор2(x: Число, y: Число)` — `ff_структура`, два `f32`-поля, тот же
  C ABI, что у raylib'овского `Vector2` (имя на panos-стороне
  кириллическое — не нужно писать латинские raylib-имена в своём коде).
- `Вектор3(x: Число, y: Число, z: Число)` — плоский `f32`-вектор для
  координат 3D.
- `Прямоугольник(x, y, ширина, высота)`, `Текстура2D` и
  `РендерТекстура2D` — ABI-совместимые типы для 2D-областей и GPU-текстур.
- `Камера3D` создаётся через `камера_перспективы(...)`. Внутренний layout
  намеренно плоский и ABI-совместим с raylib `Camera3D`, так как Panos пока
  не поддерживает вложенные `ff_структура`.
- `Цвет(r: Целое, g: Целое, b: Целое, a: Целое)` — `ff_структура`,
  четыре беззнаковых байта (0..255), тот же C ABI, что у raylib'овского
  `Color`.

### Ввод

- `клавиша_нажата(клавиша: Целое) -> Булево`
- `клавиша_вверх()` / `клавиша_вниз()` / `клавиша_влево()` /
  `клавиша_вправо()` / `клавиша_пробел()` / `клавиша_escape()` /
  `клавиша_w()` / `клавиша_a()` / `клавиша_s()` / `клавиша_d()` /
  `клавиша_r()` — коды
  клавиш raylib (`KeyboardKey`), геттеры вместо символьных констант (у
  panos пока нет механизма импорта чужих enum'ов).
- `смещение_мыши() -> Вектор2`, `левая_кнопка_мыши_нажата() -> Булево`
- `скрыть_и_захватить_курсор()` / `освободить_курсор()` — режим FPS для
  свободного обзора мышью.
- `текущий_fps() -> Целое` — значение FPS, усреднённое raylib.

## Известные ограничения

- **Путь к библиотеке захардкожен.** `внешний`-декларации требуют полный
  путь для библиотек не на стандартных путях поиска dyld/ld.so (raylib —
  не системная библиотека вроде libc). Если raylib установлен не через
  `brew install raylib` на Apple Silicon — поправьте путь в начале
  `raylib.pns` (12 строк `внешний "..." функ ...`) под свою систему,
  например `/usr/local/lib/libraylib.so` на Linux.
- **Только плоские структуры.** `ff_структура` не поддерживает вложенные
  структуры/строки/указатели как поля. `Текстура2D` и `РендерТекстура2D`
  представлены плоским ABI-совместимым layout, но более сложные типы вроде
  `Model` и `Font` пока не обёрнуты.
- **Графический цикл голодит другие panos-процессы.** planos-планировщик
  кооперативный, без преемптивности — синхронный `raylib.*`-вызов внутри
  `пока raylib.окно_должно_закрыться() == ложь цикл ... конец` не
  уступает управление другим `запусти`-процессам, пока окно не закроется.
  `pong.pns` этого не показывает (не использует процессы).

## Лицензия

Код распространяется как есть, без отдельной лицензии — то же условие,
что у [panos](https://github.com/Garius6/panos) на момент публикации.
